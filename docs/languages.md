# 解释语言与兜底：设计说明

> 依据：语言任务书（第 2 节以 2026-11-16 你在对话里的更正为准）+ 兜底增补。两份文件在 `~/.openclaw/workspace/tmp/`，本次运行无权读取工作区外的文件，内容取自对话里贴出的全文。

## 1. 检测方法

### 1.1 列出词典

`DCSCopyAvailableDictionaries()` 返回系统认识的**全部**词典（本机 87 本），包括没下载的。没下载的词典 `DCSDictionaryGetURL` 为空。

**实测踩坑**：对未下载的词典调用 `DCSCopyTextDefinition` 会让 macOS 在后台下载词典资源。开发时的第一个探针就这样，让本机从约 15 本已下载变成了 87 本全部下载。所以 `--list-dictionaries` 只探测 URL 非空的词典，查词也只用探测列表里的词典。

系统没有公开 Dictionary.app 里「勾选启用」的列表（`com.apple.DictionaryServices` 偏好里只有版本号），所以「可用」的定义是：**已下载，并且能答出英文或汉字探针**。

### 1.2 推断语言：判的是释义，不是词条里出现的字母

中日韩及其他非拉丁文字仍按字符占比判断（`native/dictlookup.m` 的 `explainLanguage`）：

| 条件（按顺序） | 判为 |
| --- | --- |
| 假名 ≥ 5% | ja |
| 谚文 ≥ 5% | ko |
| 汉字 ≥ 10%（英文词条）/ ≥ 50%（汉字词条） | 中文；繁简按 46 对只出现在一边的字计数，一边超过另一边两倍才定，否则记 `zh` |
| 天城文、西里尔、阿拉伯等其他文字 ≥ 3% | other；语言码用词典名补 |
| 汉字词条、拉丁字母为主 | en |

**拉丁字母的词条（第四轮重写）**：
1. **剥掉非释义部分**：`| 音标 |` 段，`▸`/`▶` 例句与交叉引用，单语词典 `:` 之后的例句，各类括号标签，带 IPA 字符的词，数字与单字母子项编号，多语种词性词（noun、masculine、nom femení、Gen.、Pl.……），词头本身、以词头开头的复合词（Wasserversorgung），以及与词头同词干、长度不超过词头 +2 的屈折形式（Wassers、Häuser）。同词干但更长的词会保留，避免误删释义里的同根词（governo 的 *government*）。
2. **先定语言对**：探测时用英文探针词（water、house、government、people）查每本词典，对剥离后的释义做不受约束的识别。多数票落在同一种非英语语言（≥ 2 票），就得到语言对 {en, X}；全是高置信度英语，就是英英单语；都不成立时**用词典名兜底**（如「Español-Inglés」→ es，「Malayalam」→ ml），连名字也认不出，就记 `xx?`。
3. **查词时在语言对内判**：`NLLanguageRecognizer.languageConstraints = [en, X]`，置信度 ≥ 0.6 即采用。所以同一本西英词典里，agua 判为 en，water 判为 es。

本机 58 本已下载词典的语言对：47 本由探针定出，11 本由词典名兜底（挪威语，以及阿拉伯、希伯来、印地、马拉雅拉姆、俄、土耳其、希腊、哈萨克、乌克兰、泰语这些非拉丁文字的双语词典）。

`scripts/explain_lang_test.zsh` 在本机真实词典上测了 65 个「词典 × 词」：西英、法英、德英、加英、意英、葡英两个方向，以及英英、英汉、汉英。**64/65 正确**，唯一的错误是意英词典的 `casa` 判成了 it。

探测缓存的签名里包含探测算法版本（`probe-v2`），规则一改，旧缓存就会失效。

### 1.3 缓存

探测结果按「全部词典名 + 系统版本」的 FNV 签名，缓存在 `~/Library/Application Support/Zotero/sysdict/dictionaries.json`。签名不变就直接读缓存；系统首选语言每次现读，不进缓存。

| | 耗时 |
| --- | --- |
| 首次探测（58 本） | 约 0.4–0.6 s，插件启动时后台进行 |
| 读缓存 | 约 45 ms |
| 面板「重新检测」 | 丢弃缓存，重新探测 |

### 1.4 系统首选语言

`dictlookup --list-dictionaries` 输出 `[NSLocale preferredLanguages]` 的完整列表，不只第一项。本机是 `en-US, zh-Hant-HK, zh-Hans-HK`。

## 2. 策略（`addon/content/lang.js`，纯函数）

1. **目标语言**：
   - 用户显式设置优先，否则取系统首选语言第一项；
   - 勾了「只在同语言内解释」，目标就是划词本身的语言：拉丁字母按英语处理，汉字的简繁跟随系统列表里第一个中文。
2. **允许的词典**：全部，或面板里勾选的子集。顺序为：用户 `order` 在前、按其次序；其余按已知质量（NOAD、ODE、牛津英汉、譯典通、现代汉语规范、五南、商務），再按名称。只保留能查这类词（拉丁或汉字）的词典。
3. **逐本尝试**：dictlookup 按顺序查，带 `--stop-at-lang <目标>`，遇到第一条实际释义语言等于目标的就停，并选用这一本。简繁不一致算作宽松匹配，排在精确匹配之后，并在弹窗里注明。
4. **都不满足**：默认显示明确状态（划词语言、目标语言、原因、去哪里启用），不静默回退。只有一个例外：英文词、英文目标、哪本都没收录时，保持旧版的「未收录「xxx」」写法。
5. **探测失败**（助手缺失、子进程出错）：完全按 0.3.x 的旧逻辑走。这是故障保护，不属于策略回退。

## 3. 兜底（默认关闭）

| 情形 | 触发 | 做法 | 额外模型调用 |
| --- | --- | --- | --- |
| A | 允许范围内没有一本收录这个词 | 取允许范围内排第一的词典，定出语言 L；`dictsummary --convert-to L` 按元数据和历史把词换成 L 的**一个词**；再到那本词典里查 | 1 次（换词，3 s 超时） |
| B | 有词典收录，但都不是目标语言 | 取顺序里第一本收录的词典；压义项那次调用加 `--transcribe`，直接输出目标语言 | 0 次（转写并入常规压义项调用，3 s 超时） |
| A 之后释义仍不是目标语言 | | 压义项调用同时转写 | 合计仍只多 1 次 |

关于 L 的定义：单语词典，L 就是它的释义语言，与任务书一致。**双语词典**的情况任务书没写清，我的处理是：优先取「释义是目标语言」那一侧的词头语言，让查回来的释义尽量就是目标语言。例如牛津英汉在目标为英语时 L = 中文（用汉字去查，得到英文释义）。

**可追溯**：
- `resolve()` 返回 `fallback: { kind, originalWord, convertedWord?, convertedLanguage?, dictionary, sourceLanguage?, target }`，并写进 `lookup.log`；
- 弹窗里有一行橙底说明：A 显示「已把「agua」按语境理解为英语的「water」（NOAD）」，带「查原词」按钮，会在「词典」App 里直查原词；B 显示「释义已由端侧模型从英语转写为西班牙语」，带「原文」按钮可展开原文释义；
- 转写失败时保留原语言释义，并标「（英语释义，转写失败）」；
- A 失败时显示「没有合适的词典」，并写明「兜底（A）也没成功：……」。

**缓存**：
- 选词典的顺序按（词头类型、目标语言、词典范围、用户顺序、探测签名）记忆化；
- A 的换词结果和 A/B 的义项都只放内存，键含 词 + 语言 + itemID + 历史最后 5 个词，10 分钟 TTL，不写盘。

**B 不做落地校验**：转写后与原文没有词形重合，没法比对。界面上标明「已转写」并可展开原文，以此代替校验。

## 4. 模型层

- `dictsummary --target-lang <语言>`，可取 `auto`（按原文文字推断）。en 的提示词与之前逐字相同（`promptChars` 仍为 2439 / 2966 可以佐证），中文用中文提示词，其他语言用英文提示词加「Write every sense in X」。
- 中文有语境排序时，提示里的示例用 `spring`（泉水/春季/弹簧），不用 `bank`。用 `bank` 时模型会把示例里的「金融机构」「河岸」抄进别的词，实测出现过「河口土地」。
- 中文目标的语境排序默认走候选法，直接取中英词典的中文义项，不经模型生成（见 `docs/context-rank.md` 第 2.5 节）。
- **中文的落地校验按字算**（用于可选路径 C 与无语境精简）：取汉字、去掉虚字（的是或和与及等之……），算短语里有多少字出现在原文中。没有分词器，按字比按词稳，代价是同字异义也算重合。拉丁字母照旧按词，截前 5 个字母作词干。

## 5. 已知误判与边界

- **意英词典的 `casa` 判为 it**（65 个样本里唯一的错误）：释义片段太短，受约束识别仍偏向意大利语。
- **按顺序取第一本命中**：系统英文划 *gouvernement* 时，命中的是德英词典（德语里也有这个词），不是法英词典。这符合「收录该词且释义是目标语言」的规则；想优先法英，可以在面板里调整词典顺序。
- **探针只用英文词和汉字词**，所以单语的西班牙语、德语等词典（如 Larousse、Duden）不会被列为可查拉丁词。双语词典不受影响。
- 牛津粵英雙語詞典被判为「英文词 → 英语」：汉字只占 7%，在 10% 阈值以下。它排在 NOAD 之后，不影响默认结果。
- 兜底 A 的换词会受语境影响：「政府」在标题为 *Local government debt in China* 时被换成了 debt。界面会明示原词与换后的词。
- 转写质量参差（西语里出现过错词「Involución」），所以 B 一律标「已转写」。
- 中文目标的语境排序，见 `docs/context-rank.md`「中文排序」：默认 A 在构造的 10 例上是 8/10。
- 查词延迟：命中约 50–60 ms；未收录约 85–110 ms；需要查完所有允许的词典时约 130 ms。
- **开发期副作用**：最初的探针让 macOS 在后台下载了 72 本词典（名单见 `docs/downloaded-dictionaries.md`）。因此本机「可用词典」比你实际启用过的多；西英、德英这些测试能跑通，也正是因为它们被下载了。

## 6. 偏好键

| 键（`extensions.zotero.sysdict.`） | 默认 | 说明 |
| --- | --- | --- |
| `targetLang` | `auto` | auto / en / zh-Hans / zh-Hant / ja / ko / es / fr / de |
| `sameLanguageOnly` | `false` | 只在同语言内解释 |
| `dictScope` | 空 | 允许的词典，`|` 分隔；空 = 全部 |
| `order` | 空 | 词典顺序，`|` 分隔 |
| `fallback` | `false` | 兜底 A / B |
| `rankMethod` | `candidates` | 语境排序方式：`candidates`（A，默认）或 `onestep`（C，实验） |
